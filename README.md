# flutter_clean_architecture

A Flutter starter wired for clean architecture: **Riverpod 3** (code-generated
providers), **go_router**, **Freezed**, **Dio**, build flavors and localization.
The sample feature set is a small product catalogue backed by
[dummyjson.com](https://dummyjson.com).

## Toolchain

| | |
|---|---|
| Flutter | 3.47.2 (pinned with [FVM](https://fvm.app) via `.fvmrc`) |
| Dart | 3.13.2 |
| iOS | deployment target 15.0, Swift Package Manager, UIScene lifecycle |
| Android | AGP 9.1.0 · Gradle 9.3.1 · Kotlin 2.4.0 · Java 17 |

Dependencies are managed with FVM so this project can sit alongside apps on
other SDK versions:

```bash
fvm install && fvm flutter pub get
```

Every `flutter` / `dart` command below assumes an `fvm` prefix.

## Layout

```
lib/
├── core/
│   ├── async/       AsyncValue helpers (see "Riverpod 3" below)
│   ├── networking/  Dio provider
│   ├── router/      go_router configuration
│   └── theme/       ThemeData + BuildContext extensions
├── features/<feature>/
│   ├── data/        models, repositories
│   ├── domain/      entities, use cases
│   └── presentation/providers, screens
├── l10n/            ARB files and generated localizations
├── flavors.dart     generated by flutter_flavorizr
└── main.dart
```

## Running

Flavors are `dev` and `prod`. The entrypoint is a single `lib/main.dart` that
reads Flutter's built-in `appFlavor`, so there are no per-flavor `main_*.dart`
files.

```bash
fvm flutter run --flavor dev
fvm flutter build ipa --flavor prod
fvm flutter build appbundle --flavor prod
```

VS Code launch configurations for each flavor and mode are in
`.vscode/launch.json`.

## Code generation

```bash
fvm dart run build_runner build
fvm dart run build_runner watch   # while developing
```

## Riverpod 3: use `whenSafe`, not `.when`

Riverpod 3 retries a provider that fails, so a failed first load settles as
`AsyncLoading` **with the error attached** — `isLoading` and `hasError` are both
true and there is no value. Because `AsyncValue.when` tests loading first, its
`error` branch is unreachable and the UI spins forever instead of reporting the
failure.

Use `whenSafe` from `lib/core/async/async_value_x.dart`, which resolves a hard
failure first, then any value worth rendering (so a refresh keeps showing stale
data rather than flashing a spinner), then loading. A test in
`test/async_value_x_test.dart` fails the build if `.when(` reappears in `lib/`.

## Reconfiguring flavors

Edit `flavorizr.yaml`, then:

```bash
fvm dart run flutter_flavorizr -f
```

`instructions:` is scoped to the platform processors only. `flutter:app`,
`flutter:pages` and `flutter:main` are deliberately excluded — they would
overwrite `lib/app.dart` and scaffold entrypoints this template does not use.

## Notes

- `custom_lint` / `riverpod_lint` are not included: their current releases pin
  incompatible `analyzer_plugin` ranges and cannot be resolved together.
- `android/app/flavorizr.gradle.kts` is generated and still uses AGP's legacy
  `AppExtension` API. It builds on AGP 9.1.0; revisit if a future AGP drops it.
